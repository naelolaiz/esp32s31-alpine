# 2026-10-06: Espressif baseline boots (step 2)

Flashed an existing local build of the Espressif BSP (pins in
[bsp/versions.md](../../bsp/versions.md)) and booted to the Buildroot shell.

## Boot chain as observed

| Stage | Banner | Notes |
| --- | --- | --- |
| ROM | `ESP-ROM:esp32s31-20251218` | loads SPL to 0x2f040000 (internal SRAM), DIO then QIO @ 80 MHz |
| U-Boot SPL | `U-Boot SPL 2024.07` | boots from NOR |
| OpenSBI | `OpenSBI: ESP32-S31 firmware active` | SBI v2.0, impl version 0x10006 (1.6); TIME, IPI, RFENCE, SRST, DBCN |
| U-Boot | `U-Boot 2024.07` | "DRAM: 320 KiB (effective 16.3 MiB)"; FDT at 0x40200000 relocated to 0x50ffb000 |
| Linux | `Linux version 6.18.0` | GCC 14.1.1 esp-linux, single CPU |

U-Boot prints `ERROR: reserving fdt memory region failed (addr=2f030000 size=40000 flags=4)`;
Linux then sets up that region itself as a 256 KiB DMA pool, so it looks
harmless. Linux also prints `Failed to add a System RAM resource at 50000000`.
Neither stops the boot; both are worth understanding later (learning track).

## What this answers

- **F extension:** the hart reports no F or D, so `ilp32` soft-float is not
  just the conservative choice, it is the only one.
- **Free RAM:** about 12 MB available with Buildroot's userspace, matching the
  community port's 12.7 MB estimate.
- **Rootfs placement:** the cramfs is mapped at 0x40b00000. The plan quoted
  0xC00000 from the comment in `rootfs-cramfs.sh`; the mapped address suggests
  flash offset 0xB00000 (if flash maps at 0x40000000). Check the layout config
  in esp-linux-bsp before relying on either. Resolved in step 6: the offset is
  0xC00000 and the window maps offset 0x100000 at 0x40000000 (ground-truth.md).
