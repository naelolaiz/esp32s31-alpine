# 2026-10-07: OpenRC on the board (step 14)

Alpine boots on the ESP32-S31 to a login prompt: Espressif's kernel, the
root file system on the USB stick from step 13, BusyBox init and OpenRC.
Guide: [`docs/steps/14-openrc.md`](../steps/14-openrc.md).

## Configuration

Done on the board, in the `init=/bin/sh` shell from step 13:

- The clock set by hand (`date -s` with the PC's UTC time) and
  `/var/lib/misc/openrc-shutdowntime` touched, so swclock has a reference
  at the first boot. The board has no RTC driver.
- `/etc/inittab`: the `tty1` to `tty6` gettys commented out (`CONFIG_VT` is
  off), the `ttyS0` getty enabled.
- `/etc/fstab`: `/dev/sda1 / ext4 rw,relatime 0 0`, fsck pass 0 because there
  is no `fsck.ext4` for riscv32 yet.
- `/etc/hostname`: `esp32s31`.
- Services:

```
~ # rc-update show
             bootmisc | boot
                devfs |                                 sysinit
                dmesg |                                 sysinit
             hostname | boot
            killprocs |                        shutdown
                local |      default
             mount-ro |                        shutdown
            savecache |                        shutdown
              swclock | boot
                sysfs |                                 sysinit
```

BusyBox `mount -o remount,ro /` failed with
`mount: can't read '/proc/mounts'` until `/proc` was mounted: it looks the
mount up there. The guide now mounts `/proc` first.

`mdev` was left out (moved to step 16): Alpine's `mdev` service writes
`/proc/sys/kernel/hotplug`, which needs `CONFIG_UEVENT_HELPER`, off in this
kernel.

## Boot

U-Boot prompt:

```
esp32s31> setenv bootargs earlycon=sbi console=ttyS0 root=/dev/sda1 rootfstype=ext4 rootwait rw swiotlb=128
esp32s31> booti 0x40400000 - 0x40200000
```

Second OpenRC boot, from the kernel's handover:

```
[    4.029125] Run /sbin/init as init process

   OpenRC 0.63.2 is starting up Linux 6.18.0 (riscv32)

 * Mounting /proc ... [ ok ]
 * Mounting /run ... [ ok ]

```

- The first two lines are OpenRC's own `init.sh` (`/proc`, and `/run` as
  tmpfs); then the sysinit services (devfs, sysfs; dmesg prints nothing),
  the boot services (swclock, then fsck, root and localmount pulled in by
  bootmisc, then bootmisc and hostname), and `local` in default.
- No `Caching service dependencies` and no `Clock skew detected`: `init.sh`
  restored the dependency cache that `savecache` wrote to `/var/cache/rc` at
  the previous shutdown.
- `Checking local filesystems` succeeds without running anything, because no
  `fstab` line has a pass other than 0.

## RAM

```
esp32s31:~# free
              total        used        free      shared  buff/cache   available
Mem:          14736        3336        8004          32        3396        9912
esp32s31:~# grep -A3 'cpu: 0' /proc/zoneinfo
    cpu: 0
              count:    89
              high:     459
              batch:    1
```

| KiB | Buildroot, stick in (step 13) | Alpine shell (step 13) | Alpine with OpenRC, logged in |
| --- | --- | --- | --- |
| `MemFree` | 11432 | 3396 | 7944 |
| `MemAvailable` | 10964 | 8836 | 9852 |
| `Buffers` + `Cached` | 532 | 6896 | 3396 |
| `Slab` | 1268 | 1348 | 1600 |
| `KernelStack` | 200 | 216 | 232 |
| `AnonPages` | 132 | 96 | 160 |
| `PageTables` + `Percpu` + `VmallocUsed` | 148 | 132 | 164 |
| not attributed | 1024 | 2652 | 1240 |

- With OpenRC running, Alpine leaves 9852 KiB available, about 1.1 MiB less
  than Buildroot. Processes take 160 KiB; slab is 332 KiB above Buildroot
  (ext4, its journal, and the cached directory entries and inodes of the
  files OpenRC read).
- `/proc/zoneinfo` answers step 13's open question. The per-CPU list of free
  pages held 89 pages (356 KiB) here, and its limit (`high`) is 459 pages,
  1836 KiB. `MemFree` does not count these pages. Step 13's extra 1.6 MiB of
  unattributed memory fits within that limit; most likely apk had just exited
  and its freed pages sat on the list (inferred).
- Without the list, the unattributed part is about 880 KiB, close to
  Buildroot's.

## Shutdown

`poweroff` runs the shutdown runlevel: `killprocs`, `savecache`, swclock
saving the time, `mount-ro`. The boot after it mounted the root without
`EXT4-fs (sda1): recovery complete`, so the shutdown closes ext4 cleanly.
The two boots before it did print that line: one followed an RST out of the
`init=/bin/sh` shell without a remount, and ext4 replayed its journal.
