# 2026-10-10: The cores have Zba, Zbb, Zbc and Zbs

GrieferPig's device tree lists the bit-manipulation extensions
(`rv32imafbcn_zba_zbb_zbc_zbs`) and his user space is built with them;
Espressif's device tree lists none of them. They are now checked on the
board: all four are implemented.

## The test

[`tools/bitmanip-test.c`](../../tools/bitmanip-test.c) runs 32
instructions, each alone in its own inline assembly with `.option arch`, so
the program itself stays `rv32imac` and a missing extension raises `SIGILL`
at exactly that instruction. Every result is compared with a value computed
from base instructions only.

| Extension | What it adds | Instructions tested |
| --- | --- | --- |
| Zba | shift-and-add for array addresses | `sh1add` `sh2add` `sh3add` |
| Zbb | basic bit manipulation | `andn` `orn` `xnor` `clz` `ctz` `cpop` `max` `maxu` `min` `minu` `sext.b` `sext.h` `zext.h` `rol` `ror` `rori` `orc.b` `rev8` |
| Zbc | carry-less multiplication | `clmul` `clmulh` `clmulr` |
| Zbs | single-bit instructions | `bset` `bclr` `binv` `bext` `bseti` `bclri` `binvi` `bexti` |

Built with `riscv32-alpine-linux-musl-gcc -static -O2 -march=rv32imac
-mabi=ilp32`. Before the board, QEMU 8.2 showed that the test tells both
cases apart: `-cpu max` gives `ALL PRESENT`, and
`-cpu rv32,zba=false,zbb=false,zbc=false,zbs=false` gives `SIGILL` for all
32.

## On the board

Run from the stick under GrieferPig's image (during the
[trial](2026-10-10-grieferpig-trial.md)):

```
zba: 3 of 3 instructions ok
zbb: 18 of 18 instructions ok
zbc: 3 of 3 instructions ok
zbs: 8 of 8 instructions ok
ALL PRESENT
```

All 32 lines before the summary read `ok`.

- These instructions have no state for the kernel to save and need no
  kernel or device tree support to run in user space (unlike F), so the
  result holds under our kernel too.
- His kernel runs on both cores, and this run did not pin itself to one.
  The cores are not identical: his documentation says the XespV vector
  extension works only on core 1. Which core ran the test is not recorded.

## What it means

- Programs built for this board can use `-march=rv32imafc_zba_zbb_zbc_zbs`
  (with `-mabi=ilp32` for Alpine's soft-float libraries). Alpine's packages
  stay `rv32imac`, the common base that other RV32 hardware runs too.
- Listing them in our device tree would show them in `/proc/cpuinfo` and
  to programs that ask the kernel (`riscv_hwprobe`), but would not speed up
  the kernel itself. Its Zbb string and checksum code (`CONFIG_RISCV_ISA_ZBB`)
  is patched in at boot, which needs `CONFIG_RISCV_ALTERNATIVE`, and that
  depends on `!XIP_KERNEL`: code in flash cannot be patched. GrieferPig
  compiles his whole kernel with the extensions instead (his
  `hw-reference/isa.md`). Not done here yet.
