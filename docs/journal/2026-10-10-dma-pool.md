# 2026-10-10: A 20 KiB DMA pool next to the radio (step 20, part 1)

The kernel's coherent DMA pool moved from 256 KiB at 0x2F030000 to 20 KiB at
0x2F073000, with the USB root and Ethernet still working. That frees
0x2F030000 to 0x2F072380 and 0x2F078C00 to 0x2F07CFB0 for the Wi-Fi radio.
Guide: [`docs/steps/20-sram-and-fpu.md`](../steps/20-sram-and-fpu.md),
sections 1 to 5. The why of the placement is in the
[step 19 results](2026-10-10-native-wifi-board-checks.md).

## The trial DTB

Only the built device tree changed: `images/esp32s31.dtb` decompiled with
the kernel's `dtc`, the pool node renamed and its `reg` changed, then
compiled back.

- The first attempt kept the old `reg` line next to the new one, and `dtc`
  refused it: `ERROR (duplicate_property_names): /reserved-memory/dma-pool@2f073000:reg: Duplicate property name`.
  The guide now says to replace the two lines.
- Compiling the decompiled text prints `clocks_property`, `resets_property`,
  `phys_property` and `gpios_property` warnings: references to other nodes
  became plain numbers in the text, so `dtc` cannot check them. The numbers
  are unchanged.
- Both files are 5795 bytes, and `cmp -l` counts 6 differing bytes: two
  characters of the node name, two bytes of the start, two of the size. So
  nothing else in the tree changed.

Only the DTB slot was flashed (`write-flash 0x300000`).

## On the board

```
[    0.000000] Reserved memory: created DMA memory pool at 0x2f073000, size 0 MiB
[    0.000000] OF: reserved mem: initialized node dma-pool@2f073000, compatible id shared-dma-pool
[    0.000000] OF: reserved mem: 0x2f073000..0x2f077fff (20 KiB) nomap non-reusable dma-pool@2f073000
```

```
esp32s31:~# ls /proc/device-tree/reserved-memory/
#address-cells     dma-pool@2f073000  ranges
#size-cells        name
esp32s31:~# mount | grep ' / '
/dev/sda1 on / type ext4 (rw,relatime)
```

The root is the stick, so the USB host got its coherent memory from the small
pool at boot.

Ethernet, with no cable plugged in:

`ip link set eth0 up` succeeded, and the driver went on to register its
receive queue and attach the PHY. It allocates both descriptor rings from the
pool before that, so the rings fit. The size estimate assumes 32-byte
extended descriptors; the driver says so at probe with `Enabled extended
descriptors` (GMAC 3.50 or newer), a boot line not checked here.

No USB messages in `dmesg` afterwards.

## Still open

- How much of the 20 KiB is in use is estimated (about 12 KiB: two ring
  pages and the dwc2 status buffer), not measured. Nothing failed, which only
  shows it is enough for one stick and `eth0`. A USB hub or a second USB
  device class may need more; the radio layout leaves 0x2F072380-0x2F073000
  and 0x2F078000-0x2F078C00 unused should it need to grow.
- The change lives in the trial DTB on the board. It becomes part of the
  build with `kernel/patches/0001` in the kernel rebuild of part 2 (guide
  section 6).
