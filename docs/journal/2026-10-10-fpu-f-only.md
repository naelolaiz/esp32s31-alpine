# 2026-10-10: Linux uses the F extension (step 20, part 2)

The ESP32-S31 cores have the F extension (single-precision floating point)
without D, now confirmed on the board: float instructions run in user space,
and the kernel keeps the float registers of two processes apart across
context switches. Guide:
[`docs/steps/20-sram-and-fpu.md`](../steps/20-sram-and-fpu.md), sections 6
to 9. With [part 1](2026-10-10-dma-pool.md), step 20 is done.

## The rebuild

One kernel rebuild with
[`kernel/patches/`](../../kernel/patches/) 0001 (DMA pool), 0002
(`CONFIG_FPU_F_ONLY`, `fsw`/`flw` context switch) and 0003 (`f` in the device
tree), through Buildroot's `BR2_LINUX_KERNEL_PATCH` and `make linux-dirclean`
then `make`.

- Before deleting the build directory, `BR2_LINUX_KERNEL_CONFIG_FRAGMENT_FILES`
  named only `kernel/fragments/10-block.config`. The step 6 USB storage
  options had been set in `linux-menuconfig` only, so the rebuild would have
  dropped them and the board could not have mounted the stick.
  `20-usb-storage.config` was added to the setting first.
- All three patches applied with `patch`, and both fragments were merged.
- The kernel configuration before and after differs in one line:

  ```
  267a268
  > CONFIG_FPU_F_ONLY=y
  ```

- The new DTB lists `riscv,isa = "rv32imafc_zicsr_zifencei"` and `"f"` in
  `riscv,isa-extensions`, with `dma-pool@2f073000`.
- A test build of the same tree with clang in a cloud container showed
  `__fstate_save` and `__fstate_restore` using only `fsw` and `flw`, 32 each.

DTB and kernel were flashed together (`write-flash 0x300000 images/esp32s31.dtb
0x500000 images/xipImage`).

## On the board

```
esp32s31:~# dmesg | grep -i -E 'reserved mem|isa|F but not D'
[    0.000000] Reserved memory: created DMA memory pool at 0x2f073000, size 0 MiB
[    0.000000] OF: reserved mem: initialized node dma-pool@2f073000, compatible id shared-dma-pool
[    0.000000] OF: reserved mem: 0x2f073000..0x2f077fff (20 KiB) nomap non-reusable dma-pool@2f073000
[    0.000000] riscv: base ISA extensions acfim
[    3.246123] sd 0:0:0:0: [sda] Write cache: disabled, read cache: enabled, doesn't support DPO or FUA
[    4.579529] EXT4-fs (sda1): mounted filesystem ... r/w with ordered data mode. Quota mode: disabled.
esp32s31:~# grep isa /proc/cpuinfo
isa             : rv32imafc_zicsr_zifencei_zaamo_zalrsc_zca_zcf
hart isa        : rv32imafc_zicsr_zifencei_zaamo_zalrsc_zca_zcf
```

- `acfim`: F is on, and there is no `F but not D` line.
- `zcf` (compressed float loads and stores) is not in the device tree: the
  kernel adds it on rv32 when C and F are both present. `zaamo`, `zalrsc` and
  `zca` are the parts of A and C, listed the same way.
- The stick was found and mounted, so the rebuilt kernel kept USB storage.

[`tools/fpu-test.c`](../../tools/fpu-test.c), built in the `alpine-rv32`
container with `-march=rv32imafc -mabi=ilp32` (5 lines of `fadd.s`,
`fsub.s`, `fmul.s` or `fmadd.s` in `objdump`), first under `qemu-riscv32`:

```
process 1: 456dd8f9 in all 5 rounds
process 0: 456dd8fb in all 5 rounds
OK
```

and on the board, copied there on the stick:

```
esp32s31:~# /root/fpu-test
process 0: 456dd8fb in all 5 rounds
process 1: 456dd8f9 in all 5 rounds
OK
```

- No `SIGILL`: the F instructions exist in hardware. Before this kernel any
  float instruction in user space would have been illegal, because Linux left
  the FPU off (`sstatus.FS` "Off") for every process.
- The same bits as QEMU in every round, with two processes computing at once:
  the context switch saves and restores the single-precision registers
  correctly. QEMU and the board run the same binary under IEEE single
  precision, so any register mix-up would have shown as different bits.

This closes the open question from step 2 ("no FPU"), which only read the
device tree, and settles the study's inference from Espressif's Wi-Fi
libraries being built `rv32imafc` with the single-float ABI.

## Notes

- Alpine's user space stays soft-float (`ilp32`). F is now usable by the
  kernel's radio code (step 21) and by programs built with
  `-march=rv32imafc -mabi=ilp32` like the test; a hard-float (`ilp32f`)
  Alpine would be a separate port.
- Going back needs no rebuild: a DTB without `f` (part 1's trial DTB) turns
  F off again with the same kernel.
